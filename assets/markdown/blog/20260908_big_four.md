Like many other people (programmers in particular) my life is a constant cycle of getting ideas for side projects, getting close to or even completing a minimum viable product, and then putting that project on "indefinite hiatus".

In a way AI has made it easier to cycle through these "side projects", but this isn't the post to talk about AI. What I want to outline here are my "white whale" projects. These are the side projects I've either actively maintained for a long time, or always lay in some recess of my mind.

Take this post as a soft commitment to try to push these projects beyond MVP towards something I'd be proud to share with other people, even beyond friends and family.

## The Minesweeper Document

Well, this is probably the biggest sword of Damocles swaying above my head. The minesweeper document is an ambitious project I started amid unemployment during COVID attempting to formalize minesweeper strategy and algorithms beyond what I could find online.

Right before I started my graduate program, I soft released an unfinished version of the document which I believe to genuinely contain new minesweeper insight not published elsewhere on the web.

At some point, I got really stuck with two problems. The first problem was debugging frustration on higher order probability calculations. These bugs have pretty much persisted for over 4 years at this point. Maybe AI coding has gotten good enough that it may be able to help me, although my algorithm is fairly complicated so I'm not laying out too much hope.

The other problem was a hyperfixation on the ZiNi problem. Existing solutions use stochastic heuristics to sorta locally obtain the ZiNi. I was pretty convinced there was a clean way to reduce the ZiNi problem to another problem and apply some sort of SAT solver, but I just kept running into mathematical troubles there.

Now that a lot of time has elapsed, I probably have to go back and rewrite a large portion of the document. Originally I wanted to complete and print this as a book around the time I graduated, but that is looking increasingly unrealistic.

At some point. I'll need to find some full month where I have absolutely no obligations to recalibrate and get this project back on the track of progress.

This goal will be satisfied when I have a printed version of a the document as an fully diagramed and semi peer-reviewed book.

*Goal: within 3 years*

## Tabletop Lab (name pending)

This is a project that I thought would be novel, but after market research, it's really not that unique. However, I think I bring a different spin on the idea that probably no one else will try to do.

Essentially, the core goal of this project is to create a board game scripting framework in such a way that it's easy or trivial to create, train, and evaluate AI players.

The motivation comes from having no friends who want to play the card games I want to try, and having no means of transportation to make my way to the nearest local game store to try to acquire those types of friends.

I eventually spun this into both a benefit for game preservation and a useful tool for metric-based playtesting.

The main blocker for this, like many other large side projects, is time. I sometimes am able to sneak in a couple hours of progress, but in the end scope creep blew the project up so large that it's taking a long time just to ensure I build a satisfactory framework.

Despite all the troubles, this is something I genuinely want to finish and offer to the board gaming space as an interesting tool (a bit scared of branding it with AI given the current environment, though it is AI in every sense).

Since direction is mostly clear and the issue is mostly just the time it takes to code, using a coding agent to assist development is probably the cleanest unblocker, but I've been incredibly resistant towards paying for any AI service, as it's an industry I can't really financially support with sound conscious. A path forward I'm open to is to use local LLMs to assist coding, but this is mostly an issue of hardware limitations and local models and harnesses still catching up.

This goal will be satisfied when I implement an adequate amount of games digitally, create an interface for other people to implement games, and successfully create a wide enough variety of AI to create a tourney to ELO rank AI while providing metrics for strategic and balance insights. 

*Goal: within 5 years*


## Blind playing card sorting

This project pretty much started from the desire to perform an oddly specific party trick. I want to by able to take a shuffled deck of playing cards. Flip them face down, and sort them to new deck order in-hand (no table, so bucket sorting is out).

I eventually came down to a method to pull this off, but it requires an inordinate amount of metal training and preparation, hence it sort of become a large project on its own.

The key step to this project is developing a memory system. The key to a successful memory system is that it must be personal. The most popular memory system is the PAO system, which, in order to work for a deck of cards, means I need to memorize 52x3 mappings from cards to words. If I want to extend this system to memorization tricks beyond playing cards, the most flexible size would be 100x3 mappings. Some particularities about cards also suggest that an extended PAO with 4 parts might be the ideal system, meaning 100x4 mappings.

This is quite the undertaking. If I were serious about being able to do this as soon as possible, I would probably just start filling out the spreadsheet with maps and get to memorizing. However, I wanted to take this chance to layer a bunch of things, including a card game and a worldbuilding project, and it somehow turned into a mostly artistic project.

The main blocker at the moment is that I sort of have worldbuilding disease, having to constantly consider a lot of different directions to take these mappings. In the past month however, I think I started to settle on a system for characters at least.

I've put worldbuilding a bit to the side and am very slowly filling out a spreadsheet of 52 characters, which I eventually plan to expand to 100.

As this is essentially an artistic project, I find it easier to slot in time to work on this as it differs quite a bit from active daily tasks. But since this is an artistic project, I'm progressing rather slowly as I don't really have to much experience in these types of projects, so I'm constantly learning new things.

This goal will be satisfied when I have in my hands my own designed playing cards I can use to practice my own memory system, and subsequently performing the desired party trick on a standard deck.


*Goal: 5 years*


## Rasspppy

Of all projects, this one is the oldest, as well as the project I haven't progressed on in the longest. However, it is built on the dream that I've had the held ever since high school.

In essence this project is a modern version of a music patching language that I can use to process, manipulate, and produce audio on the fly.

The end vision is live vocaloid-esque song performance. I should essentially be able to control a digital setup (skin to ableton) using patches (like max MSP) but integrated with my own algorithms for live voice synthesis in my own custom visual programming language.

Unlike the previous projects, this project actually ties close to my research (intentionally), and will still require research and experiments beyond my program, diving deep into the cutting edge.

A couple years ago, I was able to complete a proof of concept reimplementation of PD, but the main blocker is simply personal lack of research, where I simply need to track modern developments in MIR and voice synthesis.

This goal will be satisfied when I do a live performance of a cover for some song for friends/family, integrating drum kits, loops, and some system of vocal synthesis.

*Goal: However long it takes, but let's just say 8 years*
